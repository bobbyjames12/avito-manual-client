# Авито · Ручной клиент для Windows

Локальное приложение PySide6 для ручного создания объявлений о футболках.
Не требует браузера, веб-сервера или установленного Python при запуске готовой сборки.

## Запуск готовой версии

Распакуйте **всю** папку из `dist/AvitoManualClient-Windows.zip` и запустите
`AvitoManualClient/AvitoManualClient.exe`. Папка `_internal` должна оставаться рядом с EXE.
Это переносимая сборка, а не установщик. Поддерживается Windows x64.

## Как пользоваться

1. Нажмите «Новое объявление», заполните поля и добавьте JPG/PNG.
2. Выберите главное фото, переместив его на первое место. Черновик сохраняется автоматически.
3. Нажмите «В очередь / обновить». Локальная проверка покажет незаполненные поля.
4. В «Настройки S3» укажите endpoint, бакет, регион, публичный URL корня бакета и ключи.
   Пример публичного URL: `https://storage.yandexcloud.net/имя-бакета`.
   Endpoint в этом примере: `https://storage.yandexcloud.net`.
5. Оставьте отдельную автоматически созданную папку клиента. Она не должна совпадать
   с папкой существующего пайплайна. Настройте публичное чтение объектов этой папки;
   весь бакет открывать необязательно. ACL public-read нужен только для провайдеров,
   которые используют объектные ACL; по умолчанию ожидается настроенная политика чтения.
6. Нажмите «Отправить очередь». Клиент отправит фото, проверит доступность ссылок
   без авторизации, затем заменит полный XML-фид и проверит его публичное содержимое.
7. Постоянную ссылку `…/feed.xml` из настроек один раз укажите в автозагрузке Авито.
   XML или ZIP вручную на Авито загружать не нужно. Фото тоже передаются по ссылкам.
8. Дождитесь обработки в Авито и проверьте его отчёт. Клиент можно закрыть после
   отправки: файлы остаются в S3.

Редактирование: откройте отправленную карточку, измените текст/фото, нажмите
«В очередь / обновить», затем «Отправить очередь». ID сохраняется. До этого
в фиде остаётся предыдущая отправленная версия. Новая партия не удаляет
предыдущие объявления из фида. Снятие с публикации в этой версии не реализовано.

## Данные и ограничения первой версии

- База SQLite и копии фотографий: `%LOCALAPPDATA%\AvitoManualClient`.
- Один компьютер, один фид, один аккаунт; второй экземпляр блокируется.
- Ключи S3 защищены Windows DPAPI для текущего пользователя, не хранятся открытым текстом.
- «Резервная копия» сохраняет согласованную базу и фото в ZIP. Для восстановления
  закройте приложение и распакуйте содержимое в папку данных, предварительно сохранив
  её текущую копию. Перенос на другого пользователя/компьютер требует повторного ввода ключей.
- Статус «Отправлено в S3» означает только доступность фида. API статусов Авито,
  запуск обработки через API и импорт старых объявлений пока не реализованы.
- Категории сейчас ограничены футболками. Поля и XML основаны на локальном проекте
  «новый проект вб пайплайн». Это не подтверждение актуальности всех значений
  в справочниках Авито: перед рабочей публикацией нужна проверка на целевом аккаунте.
- Не перенесены автоматические подстановки остатков, примерки и генерация контента.
- Адрес фида закрепляется после первой попытки отправки. Перенос хранилища требует
  отдельной миграции. Повтор после ошибки использует тот же фид и те же ID.
- Если на аккаунте уже работает пайплайн, сначала определите, какой фид должен
  управлять объявлениями. Подмена существующей ссылки без переноса старых объявлений
  не является миграцией; общий фид двух программ в этой версии не реализован.

## Разработка и проверки

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe main.py
.\.venv\Scripts\python.exe -m unittest discover -s tests -p test_*.py -v
.\.venv\Scripts\python.exe tests\smoke_ui.py
.\build.ps1
```

Основные тесты проверяют версии очереди, сохранение прежних объявлений в полном фиде,
обрыв отправки, запрет обновления XML при недоступном фото, неизменяемые фотографии
и резервную копию. Smoke-тест проверяет нативное окно, ввод, очередь, дублирование
и DPAPI без реальной отправки в S3/Авито.
